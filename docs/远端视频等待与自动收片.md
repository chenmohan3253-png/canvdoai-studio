# 远端视频等待与自动收片

## 修复的问题

本地原先最多连续查询 25 分钟。超过窗口时，远端仍为排队或生成中，本地却把画布任务标成 `FAILED`。远端实际可能随后成功，原任务 ID 也已保存，但需要人工再次运行节点收取结果。

本补丁把“查询窗口结束”“查询暂时断网”“已成功但成品暂时下载不了”表示为 `WAITING_PROVIDER`。默认 15 秒后继续按原 ID 查询；成功后自动保存项目视频素材、节点版本和任务完成状态。此过程不会重新上传参考素材，不会调用创建视频任务接口。

软件重新打开后，会自动恢复带保存 ID 的等待任务，并识别旧版本“仍在运行；已保存ID”的本地失败记录。账户或节点、引用素材已变化时暂停，避免将旧结果挂到新请求。供应商明确返回失败时才按远端失败处理；提交结果未知且没有远端 ID 时，续查入口拒绝创建新任务。

## MCP 调用

读取状态继续使用 `get_task_status`。新状态 `WAITING_PROVIDER` 表示任务正在自动续查，返回的 `remoteId` 是原远端任务 ID。

需要立即检查或恢复收片时使用：

```json
{"name":"resume_provider_task","arguments":{"taskId":"原画布任务ID"}}
```

该工具只接受 `taskId`，不接受 `force`、模型参数或 `confirmCost`。它复用原本地任务记录与保存的 provider key，不创建新本地生成任务或远端视频任务。缺少唯一远端 ID、账户不同、节点或引用发生变化时返回错误。

本地对应入口为 `POST /api/studio/provider/resume`，请求体仅为 `{"taskId":"..."}`。画布“最近任务”提供“查询原任务并收片”按钮。正常等待期间无需点击，自动续查会持续执行。

收片后会完成仅引用现有素材的输出节点。整张画布中如果还有尚未提交的后续生成节点，保持 `PAUSED`，避免仅查询操作顺带产生新的生成请求。已归档成功的任务再次查询不会新增候选版本。

## 当前交付状态

此功能包含在 v1.1.18 桌面集成测试版中。升级前保存编辑并确认生产任务状态，安装后重开软件；Codex 需重新加载 MCP 连接才能看到新工具。发布验证使用模拟供应商和本地临时测试库，未额外发起收费生成。供应商的 `manual_review` 可能同时携带失败说明，当前通用等待提示不能单独作为远端仍在生成的证明，需核对原任务回执；此类状态不要重复提交。
