# 长视频视觉分析与断点恢复说明

## 数据流

1. 原片通过桌面软件的分片上传写入本机应用数据目录，文件不会交给视觉模型服务器。
2. 软件内置的 FFprobe 读取媒体信息；内置 FFmpeg 在本机检测镜头边界和运动强度。
3. 普通镜头抽取一张关键帧。命中运动阈值的镜头在本机截取 2～5 秒低清临时片段，并抽取三张有顺序的时间帧。当前 `qwen3-vl:4b` 链路发送三张压缩时序帧，不上传低清 MP4；这样既保留动作顺序证据，又避免依赖非标准的视频输入协议。
4. 关键帧按每批最多八张，以 OpenAI-compatible `/v1/chat/completions` 请求发送到视觉分析服务。
5. 每完成一个视觉批次，软件立即把批次指纹和结构化结果写入本机分析任务状态。重启后只提交未完成批次。
6. 全部分析结果写入项目 SQLite 后，关键帧、动态预览、音频块、分析状态文件和重复源片缓存自动删除。桌面端记录本次清理是“已清理”还是“等待保留期回收”，不会再静默忽略清理失败。

## 当前生产边界

- 源片时长：最长 60 分钟；本轮重点验收 30 分钟。
- 源片大小：最长 5 GiB，使用 6 MiB 分片上传，可从已完成分片继续。
- 镜头分析：默认最多 400 个真实镜头，内部安全上限 600，可用环境变量调整。
- 动态镜头：默认最多对运动评分最高的 160 个镜头建立 2～5 秒低清临时序列，避免长片产生无界临时文件。
- 生成单元：最多 400 个；单个长镜头会按 Seedance 15 秒上限拆分。
- 视觉请求：每批最多八张图片；同一动态镜头的三张时序帧不会拆到两个批次。

## 断点和清理语义

- 分片上传断点、FFmpeg本地任务和视觉批次断点互相独立。
- 视觉批次使用模型ID、镜头号、时间码和序列位置形成稳定SHA-256指纹；更换视觉模型后不会误用旧模型结果。
- 只有项目JSON已经成功写入SQLite之后才调用临时清理接口。
- 如果程序在结果入库前断电，分析素材和批次断点会保留，以便恢复；不会因定时清理删除仍有任务状态引用的素材。
- 无任务状态引用的孤立临时目录和源片缓存会在超过保留期后清理；默认保留期为24小时。

## 视觉服务配置

接口设置页提供独立的“视觉 API Base URL”“视觉 API Key”“视觉模型 ID”。局域网视觉服务可填写：

```text
Base URL: http://127.0.0.1:8000/v1
Model: qwen3-vl:4b
```

密钥必须由服务端管理员提供并保存在Windows系统加密存储中，不要写入项目文件、日志或安装包。

“测试视觉能力 / 读取模型”会调用 `/v1/models`，随后提交一张软件内置的1像素测试图验证图片输入能力；不会上传用户视频。
