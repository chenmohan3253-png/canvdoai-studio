# CanvDoAI MCP 视频生成与状态判断

适用于本机所有视频制作项目。使用 CanvDoAI 专用 MCP，不是 Canva 插件。保留各项目原定剧本、模型、分辨率、画幅、声音和已审核素材。

## 最短执行流程

1. `list_projects` → `list_canvases` → `get_canvas`，锁定唯一 `projectId/canvasId/nodeId`。以当前正式制作包和素材 ID 为准，不按相似文件名跨项目猜测。
2. 检查该镜头最新任务。如果已有远端 ID，读取 `get_task_status` 或 `resume_provider_task` 继续查询；不创建第二单。
3. `get_video_route_limits` 读取精确模型的当前路由能力。最多 15000 字仅适用于已向供应商确认并在该路由、该模型保存的覆盖值，不是所有模型的通用上限，也不是提示词最低字数。
4. `prepare_canvas_video_request` 检查实际待发的完整提示词、参数和本项目素材映射。预检只 GET 目录，不上传、不提交。
5. 预检成功且本次生成已获用户授权、没有在途或结果未知的同镜任务后，调用 `run_canvas_node`，传入准确 `canvasId`、`nodeId`、`confirmCost:true`。常规首次运行 `force:false`。该调用才会上传素材并提交视频。
6. 保存本地任务 ID、提交时间、远端 ID 和实际状态；持续查询同一任务，返回视频后再检查时长、分辨率、声音、人物及剧情。

## 不要把这些状态混为一谈

| 看到的结果 | 证明什么 | 下一步 |
|---|---|---|
| 模型列表读取成功 | 接口返回了当前 Key 可见模型 | 继续检查该镜头参数和素材 |
| 预检成功，附件还没上传 | 本地参数和素材映射检查已通过，上传尚未发生 | 授权范围内运行节点 |
| 有远端任务 ID、queued/running | 供应商已经接单，还没返回成片 | 按原 ID 查询 |
| succeeded 且视频已收回 | 生成和下载完成 | 检查成片，合格后采用 |
| 历史 HTTP 422 | 某一次提交被拒绝；必须看任务创建时间和原回执 | 修正具体请求，检查是否已有新尝试 |
| UNKNOWN / 网络超时 | 无法确定原请求是否已被接受 | 先核对原幂等键或远端 ID，不盲目重投 |

`attachmentsPendingUpload=true`、`requestBodyComplete=false` 和 `providerAccepted=false` 在带素材的只读预检阶段是正常值。不要反复预检等待它们变 true，不要因此创建新画布，也不要为了让字段变真另做收费测试。1.1.20 新增的 `preflight.status=PASSED` 只证明本地校验通过，不能冒称供应商已接受。

`get_task_status.statusContext` 会区分记录创建时间与本次观察。精确核定的 `providerCorrection.state=REJECTED` 保留原错误供追溯；同节点 `newerAttempt` 存在时先读取新任务。原始 HTTP 422 的具体字段以脱敏的 `detail/errors/requestId` 为准，不能把旧记录当成当前新错误。

已明确拒绝且修正参数后，依照已有生成授权才可建立一次新的尝试；若相同输入被防重记录拦住，核对后明确使用 `force:true`，保存新旧任务关联。禁止用 force 绕过 UNKNOWN、在途任务或质量问题。

## 跨项目接续

- 同一集同一镜由原制作聊天负责提交，其他聊天只读检查，避免双重下单。
- 软件由平台维护聊天统一更新；制作聊天不要并行改写 app.asar 或全局接口配置。
- 必要参考图的脸、动作因果或场景错了，先定点修正；普通小动作由提示词表达，不需要等待全季素材完成才开始已经准备好的第一集。
- 新指令只改变当前被用户放行的制作范围。归档、已交付和明确停止的项目不因为软件升级自动重做。
- 报告分清“已通知”“已准备”“已提交”“已返回”“已验收”；只有实际回执和视频才能证明生产进展。
