# CanvDoAI Studio 1.1.20 更新说明

本版修复“只读预检的附件待上传被误解为失败”和“历史错误被误解为刚刚提交失败”的提示问题，保持已有任务、防重复提交和项目隔离。

## 视频制作状态

- 检测到模型只代表当前接口能返回模型目录；不能证明素材上传、具体请求和视频生成已成功。
- MCP `prepare_canvas_video_request` 成功时新增 `preflight.status=PASSED`，明确范围是本地请求与当前路由目录校验，并提示下一步调用 `run_canvas_node`。
- 只读预检不上传、不生成，因此 `attachmentsPendingUpload=true`、`requestBodyComplete=false` 和 `providerAccepted=false` 是带参考素材预检的正常结果。实际运行时先上传素材，再建立视频任务；供应商是否接受以实际回执为准。
- 预检通过不解除已有任务的防重保护，也不自动授权扣费。已有远端 ID 应继续查询；结果未知的请求应先核对。

## 历史错误

- 画布最近任务显示创建时间；MCP 读取任务返回 `statusContext`，说明本次读取只是保存状态，没有重新生成。
- 对经过精确任务 ID 证据核定的历史 HTTP 422 显示 `REJECTED` 更正说明和核定时间，保留原消息，不覆盖历史。
- 同一节点有更新尝试时，指向更新任务 ID。不会根据错误文字猜测归属，也不会自动重试。

## 其他项目如何使用

按 [MCP 视频生成与状态判断](MCP-视频生成与状态判断.md) 操作。继续使用每个项目已确认的剧本、参考图、声音、模型和规格。版本升级不会重建项目、清空记录、重新提交已完成视频，也不会自动恢复归档项目。

1.1.19 的按路由与模型设置已确认提示词上限、完整提示词及明确拒绝处理继续保留。安装包仍为未配置企业代码签名的 Windows x64 桌面集成测试版；具体供应商与全部模型的生产能力应以各自真实回执为准。
