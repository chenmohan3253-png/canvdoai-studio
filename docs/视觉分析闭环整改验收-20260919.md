# 视觉分析闭环整改验收（2026-09-19）

## 已完成

- Windows 安装包继续内置 FFmpeg 与 FFprobe；原片拆镜、运动评分、抽帧、音轨抽取与成片合成均在本机执行。
- 普通镜头只向视觉接口提交一张压缩关键帧；高运动镜头本机建立 2～5 秒低清临时序列，并提交三张有顺序的压缩帧。
- 视觉请求每批最多八张图片，同一动态镜头的三张时序帧不会拆批。
- 模型输出强制为 JSON，客户端校验并保存人物、场景、动作、构图、OCR、运动评分和置信度。
- 每批完成后立即保存 SHA-256 批次指纹和结构化结果；重启只继续未完成批次。
- 结果进入本机 SQLite 后再调用临时素材清理；界面显示“已清理”或“等待回收”。即时清理失败时，服务端保留期任务继续回收孤立文件。
- 软件内提供视觉接口、视频接口、报价与客服联系入口；生产密钥不写入源码、文档或安装包。

## 当前兼容策略

OpenAI-compatible `/v1/chat/completions` 没有统一的视频二进制输入规范，当前部署模型 `qwen3-vl:4b` 使用多图输入。因此动态镜头采用三张时序帧，而不是把 MP4 伪装成标准接口能力。后续只有在服务端明确声明并通过真实视频输入测试后，才启用低清片段直传。
